## 4.0 模板总览

NPU 算子可分为**六大类**，每类有对应的编写模板：

| 模板 | 类型 | 引擎 | 典型算子 | 核心模式 | 对应第 2 篇 API | 优化详解 |
|------|------|------|---------|---------|----------------|---------|
| A | Gather/Vector | MTE2+SimtVF | Gather | DMA 搬运 + 线程并行 | T.copy + SimtVF | → 第 5 篇 § 5.2-5.3 |
| B | GEMM/Cube | Cube+MTE2 | MatMul | T.gemm + L1 流水 + dual_copy | T.gemm + T.Pipelined | → 第 5 篇 § 5.3-5.5 |
| C | Flash Attention | Cube+SimdVF | MHA/GQA | 双 GEMM + online softmax | T.gemm + SimdVF | → 第 5 篇 § 5.4 |
| D | 归约/Norm | SimdVF | RMSNorm | Fragment trick + reducer | alloc_reducer | → 第 5 篇 § 5.2 |
| E | 量化/Cast | SimdVF | per_token_cast | amax 归约 + vcvt 量化 | vld2+vcgmax+vcvt | → 第 5 篇 § 5.7 |
| F | TopK/选择 | SimdVF | MoE TopK | 选择排序 + scatter | vcmps+vselr+vscatter | → 第 5 篇 § 5.2 |

### 选型决策树

```
算子输入输出特征
    │
    ├─ 有 GEMM 计算？
    │   ├─ 是 → 有 softmax？
    │   │       ├─ 是 → 模板 C (Flash Attention)
    │   │       └─ 否 → 模板 B (GEMM/Cube)
    │   └─ 否 → 有归约？
    │       ├─ 是 → 有类型转换？
    │       │       ├─ 是 → 模板 E (量化/Cast)
    │       │       └─ 否 → 模板 D (归约/Norm)
    │       └─ 否 → 有 gather/scatter？
    │           ├─ 是 → 模板 A (Gather/Vector)
    │           └─ 否 → 有选择/排序？
    │               └─ 是 → 模板 F (TopK/选择)
    └─ 以上都不是 → 需要新模板
```

## 4.1 模板 A：Gather / Vector 类算子

### 4.1.1 文件

- `gather.py` — 基础版本
- `gather_opt.py` — 优化版本

### 4.1.2 核心结构

```python
@tilelang.jit(pass_configs={
    PassConfigKey.TIR_DISABLE_VECTORIZE: True,
    PassConfigKey.TL_DISABLE_DATA_RACE_CHECK: True,
    PassConfigKey.TL_ENABLE_FAST_MATH: True,
})
def gather_kernel(D, dtype, index_dtype):
    n, m = T.dynamic("n"), T.dynamic("m")

    # ① 自适应 tiling：根据 D 选择最优 tile size
    BD = min(tilelang.next_power_of_2(D), C)      # D≤4: BD=4, D≤128: BD=128, else: BD=C
    BM = C // BD                                   # BM*BD = C (常量)

    # ② 纯 vector 算子用 64 个 vec cores
    num_cores = get_num_vec_cores()                 # 64

    @T.prim_func
    def main(
        input_ids: T.Buffer((n,), index_dtype),     # [n] 索引
        embedding_table: T.Buffer((m, D), dtype),   # [m, D] 嵌入表
        output: T.Buffer((n, D), dtype),             # [n, D] 输出
    ):
        with T.Kernel(num_cores) as pid:
            shared = T.alloc_shared((BM, BD), dtype)  # UB 缓冲

            # ③ 持久化调度 + 4 级流水
            for tile_idx in T.Persistent([T.ceildiv(n, BM)], num_cores, pid):
                base = tile_idx * BM

                # ④ 逐行 T.copy DMA（替代标量读）
                for i in T.Pipelined(BM, num_stages=4):
                    row = base + i
                    if row < n:
                        idx = input_ids[row]
                        # T.copy DMA 搬运一行（连续 D 个元素）
                        T.copy(embedding_table[idx, :D], shared[i, :D])

                # ⑤ 写回 GM
                T.copy(shared, output[base:base+BM, :D])

    return main
```

### 4.1.3 关键设计

| 设计点 | 说明 | 原因 |
|--------|------|------|
| **D 分支策略** | D≤4/≤128/else 选择不同 BD | 小 D 时减少 tile 开销，大 D 时增大连续搬运粒度 |
| **SimtVF 展平 1D** | 将 2D 访问展平为 1D 线程并行 | 减少嵌套循环开销 |
| **T.copy DMA 替代标量读** | 用 MTE2 DMA 替代 SimtVF 逐元素读 | DMA 带宽远高于标量 L2 miss |
| **num_stages=4 流水** | 4 级流水隐藏 HBM 延迟 | MTE2 加载与 VEC 计算重叠 |

### 4.1.4 性能特征

- 瓶颈：Vector 标量读 → T.copy DMA 替换；Scalar 循环开销 → 批量化 BM 行一批
- 性能结论：d=128 优化后 3.4x 加速，带宽 11%→39%
- 完整优化过程 → 详见第 5 篇 § 5.2-5.3

### 4.1.5 访问模式对比

| 访问模式 | GPU 方案 | NPU 方案 | NPU 性能 |
|---------|---------|---------|---------|
| 连续 DMA 搬运 | TMA / cp.async | T.copy（MTE2/MTE3） | 接近 GPU |
| 不规则行 gather | TMA 硬件 gather | 逐行 T.copy（每行连续） | 2~4x 慢 |
| 逐元素标量 gather | thread 读 GM | SimtVF 标量读（L2 miss） | 10x+ 慢 |

### 4.1.6 Gather 算子优化经验总结

#### 4.1.6.1 典型示例：d=128 场景优化全过程

**场景描述**：`output = embedding_table[input_ids]`，其中 `input_ids.shape = [131072]`，`embedding_table.shape = [131072, 128]`。

**优化轮次记录**：

| 轮次 | 优化策略 | 代码改动 | 延迟 (us) | 带宽利用率 | 加速比 | 瓶颈变化 |
|------|---------|---------|-----------|-----------|-------|---------|
| 基线 | SimtVF 标量逐元素读 | — | 296 | 11% | 1.0x | VEC 标量读主导 |
| R1 | T.copy DMA 替换标量读 | `T.copy(table[idx,:D], shared[i,:D])` 替代逐元素读 | 120 | 27% | 2.47x | MTE2 DMA 主导 |
| R2 | 批量化 BM tiling | `BD=128, BM=C//BD` 增大批次 | 95 | 34% | 3.12x | T.copy 行开销 |
| R3 | num_stages=4 流水 | `T.Pipelined(BM, num_stages=4)` | 87 | 39% | 3.40x | T.copy 行开销 |
| R4 | T.Persistent 64 cores | `T.Persistent([...], num_cores, pid)` | 65 | 52% | 4.55x | T.copy 行开销（已近极限） |

**最终结果**：296us → 65us（4.55x 加速），带宽 11% → 52%

#### 4.1.6.5 各 D 值瓶颈分类与优化策略

| D 范围 | 瓶颈类型 | 带宽范围 | 可优化? | 优化策略 |
|--------|---------|---------|---------|---------|
| D ≤ 4 | 启动开销 (数据仅 2MB) | 1.8% | 否 | 数据量太小，无需优化 |

| 128 < D ≤ 1024 | T.copy setup 开销 | 38% | 有限 | UB 限制 num_stages，增大 BD |
| D > 1024 | **MTE2 随机读带宽** | **66-73%** | **否** | 已达硬件极限，终止优化 |

#### 4.1.6.6 负结果记录（已尝试但无效的优化）

| 优化项 | 效果 | 原因 | 适用条件 |
|--------|------|------|---------|
| 减小 C (8192) 降低 BM 串行迭代 | d=656 无变化, d=128 退化 | 瓶颈非串行迭代数，而是 T.copy setup 开销 | — |
| 提高 SimtVF 阈值覆盖 d=656 | 未实施 | 标量读比 DMA 更低效 (656 次单独读 vs 1 次 DMA) | D > 16 时 DMA 总优于标量 |
| 增加 num_stages (>4) | 不可行 | UB 限制: d=656 时 4×64KB=256KB 已满 | UB 容量 = BD × dtype_size × num_stages ≤ 256KB |

#### 4.1.6.7 Gather 类算子可复用经验总结

**经验 1：DMA 优先原则**
- 任何标量 GM 读都应替换为 T.copy DMA
- DMA 带宽远高于标量 L2 miss（10x+ 差距）
- 代码模式：`for i: T.copy(table[idx[i]], shared[i])` 替代 `for i,j: shared[i,j] = table[idx[i],j]`

**经验 2：D 分支自适应 tiling**
```python
# 根据 D 值选择最优 tile size
if D <= 4:    C = 1024   # 小 D: 减少 tile 开销
elif D <= 128: C = 2048  # 中小 D: 平衡
else:          C = 16384  # 大 D: 增大连续搬运粒度
BD = min(next_power_of_2(D), C)
BM = C // BD
```

**经验 3：两分支架构**
- `BD ≤ 16`：SimtVF 标量 gather — Vector 单元逐元素读取（小 D 时开销低于 DMA setup）
- `BD > 16`：批量 T.copy DMA — MTE2 引擎按行 DMA 读取，`num_stages=4`
- `BD > 8192`：逐行 T.copy — BM=1, 1D UB, 2D 循环（超大 D 避免 UB 超容）

**经验 4：num_stages 上限由 UB 容量决定**
```python
# UB 容量约束: BD × dtype_size × num_stages ≤ 256KB
max_stages = 256 * 1024 // (BD * dtype_size)
num_stages = min(4, max_stages)  # 实际取 min(4, 上限)
```

**经验 5：大 D 场景提前判定硬件极限**
- 当 `mte2_ratio > 95%` 且 `mte2_wait_ratio > 95%` 时，大概率已达 HBM 随机读极限
- 随机 HBM 访问有效带宽为峰值的 50-70%，带宽利用率 > 65% 即可判定为硬件极限
- **不要在大 D 场景浪费优化时间**，应转向其他算子

**经验 6：ZOS 变体优化策略（Speculative Decoding 相关 Gather）**
- **SimtVF 1D 展平**：将 (seq, j, r) 三维访问展平为 1D 线程并行，每 thread 处理 1 个输出元素
- **Metadata DMA preload**：seqlens_q, cu_seqlens_q, remap 等元数据批量 DMA 到 UB
- **q_base 简化**：利用 inclusive cumsum 恒等式 `cu_seqlens_q[i] - seqlens_q[i] == cu_seqlens_q[i-1]`，消除边界分支

**经验 7：优化优先级排序**
```
P0: T.copy DMA 替换（2-5x，0.5h）→ 必做
P1: num_stages=4 流水（1.2-1.5x，1h）→ 推荐
P2: T.Persistent 64 cores（1.1-1.3x，1h）→ 可选
P3: 判定硬件极限（0，0.5h）→ 大 D 必做
```

## 4.2 模板 B：GEMM / Cube 类算子

### 4.2.1 文件

- `example_gemm.py` — 推荐入门

### 4.2.2 核心结构

```python
def gemm(M_DIM=8192, K_DIM=8192, N_DIM=8192, dtype="bfloat16", out_dtype="float32"):
    NUM_BLOCKS = 32
    TILE_M, TILE_N, TILE_K = 256, 256, 256  # bf16: TILE_K=256
    M_TILES = M_DIM // TILE_M
    N_TILES = N_DIM // TILE_N
    K_TILES = K_DIM // TILE_K
    OUT_TILES = M_TILES * N_TILES
    NUM_STAGES = 2

    # ① aswt_swizzle macro：CUTLASS 风格 swizzle
    @T.macro
    def aswt_swizzle(tile_idx):
        m_tile = T.alloc_var("int32")
        n_tile = T.alloc_var("int32")
        row_idx = tile_idx // N_TILES // WINDOW
        if row_idx < MAIN_ROW:
            m_tile = row_idx * WINDOW + tile_idx % WINDOW
            n_tile = (tile_idx // WINDOW) % N_TILES
        else:
            tail_idx = tile_idx - MAIN_ROW * WINDOW * N_TILES
            m_tile = MAIN_ROW * WINDOW + tail_idx % TAIL_WIN
            n_tile = (tail_idx // TAIL_WIN) % N_TILES
        if row_idx % 2 != 0:
            n_tile = N_TILES - 1 - n_tile    # 奇数行反向
        return m_tile, n_tile

    @T.prim_func
    def main(
        X: T.Buffer((M_DIM, K_DIM), dtype),
        W: T.Buffer((N_DIM, K_DIM), dtype),   # 注意：[N, K] 布局
        C: T.Buffer((M_DIM, N_DIM), out_dtype),
    ):
        with T.Kernel(NUM_BLOCKS) as bx:
            # ② L0C 累加器 + L1 缓冲
            res = T.alloc_l0c((TILE_M, TILE_N), "float32")
            x_l1 = T.alloc_l1((TILE_M, TILE_K), dtype)
            w_l1 = T.alloc_l1((TILE_N, TILE_K), dtype)
            temp = T.alloc_shared((TILE_M // 2, TILE_N), out_dtype)

            # ③ 持久化调度
            for tile_idx in T.Persistent([OUT_TILES], NUM_BLOCKS, bx):
                m_tile, n_tile = aswt_swizzle(tile_idx)

                # ④ K 维流水
                for kt in T.Pipelined(K_TILES, num_stages=NUM_STAGES):
                    # GM → L1（dn2nz 自动转换）
                    T.copy(X[m_tile*TILE_M:(m_tile+1)*TILE_M, kt*TILE_K:(kt+1)*TILE_K], x_l1)
                    T.copy(W[n_tile*TILE_N:(n_tile+1)*TILE_N, kt*TILE_K:(kt+1)*TILE_K], w_l1)
                    # L1 × L1 → L0C（Cube GEMM）
                    T.gemm(x_l1, w_l1, res,
                           transpose_B=True,
                           clear_accum=(kt == 0),
                           unit_flag_ctrl=T.Select(kt == K_TILES-1, UF_3, UF_2))

                # ⑤ L0C → GM（FixPipe 输出）
                T.dual_copy(res, temp, unit_flag_ctrl=UF_3)
                T.dual_copy(temp, C[m_tile*TILE_M:(m_tile+1)*TILE_M, n_tile*TILE_N:(n_tile+1)*TILE_N])

    return main
```

### 4.2.3 关键设计

| 设计点 | 说明 | 参数 |
|--------|------|------|
| **transpose_B=True** | 强制约束，权重 [N,K] 布局 | — |
| **clear_accum=(kt==0)** | 首帧清零，后续累加 | — |
| **unit_flag_ctrl** | FixPipe 重叠：UF_2 中间帧，UF_3 尾帧 | `T.Select(kt==K_TILES-1, UF_3, UF_2)` |
| **aswt_swizzle** | CUTLASS 风格 swizzle 消除 L1 bank conflict | 奇数行反向遍历 |
| **HF32** | 高精度 fp32 模式 | `T.set_hf32_mode("nearest_zero")` |
| **TILE_K 选择** | bf16=256, fp32=128（L1 512KB 约束） | — |

### 4.2.4 可调参数

| 参数 | 选项 | 选择依据 |
|------|------|---------|
| `TILE_M / TILE_N` | 128 / 256 | L1 容量 + Cube 效率 |
| `TILE_K` | 128 (fp32) / 256 (bf16) | L1 容量约束: 2*(M+N)*K*dtype ≤ 512KB |
| `NUM_STAGES` | 2 / 3 / 4 | UB 容量 + HBM 延迟 |
| `NUM_BLOCKS` | 32 (Cube cores) | 硬件核数 |

### 4.2.5 变体

| 变体 | 说明 | 关键修改 |
|------|------|---------|
| **Split-K** | K 维切分到多核 | `T.set_atomic("add")` + 多核累加 |
| **MixedKernel** | Cube + Vector 混合 | `T.MixedKernel()` |
| **UB merge** | UB 合并优化 | `MergeUBAllocations` pass |
| **block-scaled** | MXFP8/MXFP4 量化 GEMM | `scale` 参数 + `mad_mx` |

## 4.3 模板 C：Flash Attention

### 4.3.1 文件

- `flash_attention/core.py` — MHA/GQA 共用核心

### 4.3.2 核心结构

```python
@dataclass(frozen=True)
class FwdTiling:
    block_q: int = 128       # BR: query tile size
    block_kv: int = 128      # BC: KV tile size
    num_stages: int = 3      # 流水深度

def flash_attention_fwd(q_len, kv_len, head_dim=128):
    BR = 128  # block_q
    BC = 128  # block_kv (= 2 * VL, VL=64 for fp32)
    PIPELINE_STAGES = 3

    @T.macro
    def qk(kv, K, Q_shared, K_shared, qk_a_l0, qk_b_l0, qk_acc_l0c, S_ub):
        # ① Cube: Q @ K^T → S
        T.copy(K[kv*BC:(kv+1)*BC, 0:D], K_shared[0:BC, 0:D])
        T.copy(Q_shared[0:BR, 0:D], qk_a_l0)
        T.copy(K_shared[0:BC, 0:D], qk_b_l0)
        T.gemm(qk_a_l0, qk_b_l0, qk_acc_l0c, transpose_B=True, clear_accum=True)
        T.dual_copy(qk_acc_l0c, S_ub[0:ROWS, 0:BC])  # L0C → UB

    @T.macro
    def softmax(S_ub, P_nz_ub, m_ub, l_ub, ...):
        with T.SimdVF(latency=735):
            # ② Vector: online softmax (vmax/vsub/vexp/vmul)
            softmax_full = S.pset(32, "PAT_ALL")
            # ... online softmax 实现
            # NZ 布局 packing: vsstb stride=128
            S.vsstb(dst_nz_ptr, p_b16, stride=128)

    @T.macro
    def pv(kv, V, P_nz_ub, V_shared, pv_a_l0, pv_b_l0, pv_acc_l0c, O_ub):
        # ③ Cube: P @ V → O
        T.copy(V[kv*BC:(kv+1)*BC, 0:D], V_shared[0:BC, 0:D])
        T.copy(P_nz_ub[0:BC, 0:BR], pv_a_l0)   # P 已是 NZ 布局
        T.copy(V_shared[0:BC, 0:D], pv_b_l0)
        T.gemm(pv_a_l0, pv_b_l0, pv_acc_l0c, transpose_B=True)
        T.dual_copy(pv_acc_l0c, O_ub[0:ROWS, 0:D])

    @T.prim_func
    def main(Q, K, V, O, ...):
        with T.Kernel(NUM_BLOCKS) as bx:
            # 分配所有 buffer
            Q_shared = T.alloc_shared((BR, D), dtype)
            K_shared = T.alloc_shared((BC, D), dtype)
            # ...

            for m in T.Persistent([NUM_M_TILES], NUM_BLOCKS, bx):
                T.copy(Q[m*BR:(m+1)*BR, 0:D], Q_shared)

                for kv in T.Pipelined(NUM_KV_BLOCKS, num_stages=PIPELINE_STAGES):
                    qk(kv, K, Q_shared, K_shared, ...)     # Cube: QK^T
                    softmax(S_ub, P_nz_ub, m_ub, l_ub, ...) # Vector: softmax
                    pv(kv, V, P_nz_ub, V_shared, ...)       # Cube: PV

                # 写回输出
                T.copy(O_ub, O[m*BR:(m+1)*BR, 0:D])
```

### 4.3.3 关键设计

| 设计点 | 说明 |
|--------|------|
| **Cube 负责两次 GEMM** | QK^T 和 PV，利用 Cube 高算力 |
| **SimdVF 负责 online softmax** | vmax/vsub/vexp/vmul 向量指令 |
| **NZ 布局 packing** | `make_ascend_compact_nz_layout` + `vsstb stride=128` 预打包 NZ |
| **@T.macro 捕获编译期变量** | BR/BC/scale 在编译期固定 |
| **pin head_dim=128** | SIMD packing 路径硬编码 D=128 |
| **L0C→UB 中间结果搬运** | `T.dual_copy` 将 GEMM 结果搬到 UB 供 softmax |

### 4.3.4 数据流

```
Cube: Q @ K^T → L0C → UB(S)
                          ↓
Vector: online softmax    → UB(P, NZ 布局)
                          ↓
Cube: P @ V → L0C → UB(O)
                          ↓
                    MTE3: UB → GM
```

```python
def rms_norm_fwd(batch, d, dtype="float32"):
    N_CORES = 64                              # 64 个 vector cores
    TILE = tilelang.next_power_of_2(d)        # 对齐到 2 的幂
    threads = 256 if TILE > 4096 else 128     # 自适应线程数

    @T.prim_func
    def main(X, Y, W, RSTD, eps):
        with T.Kernel(N_CORES) as core_id:
            # ① Double buffer
            w_ub = T.alloc_shared((d,), dtype)         # 权重 UB
            x_ub = T.alloc_shared((TILE,), "float32")  # 输入 UB
            y_ub = T.alloc_shared((TILE,), "float32")  # 输出 UB

            # ② 权重只加载一次
            T.copy(W[:d], w_ub[:d])

            # ③ 持久化 + 双缓冲流水
            for t in T.Pipelined(n_tokens_per_core, num_stages=2):
                base = (t * N_CORES + core_id) * d
                T.copy(X[base:base+d], x_ub[:d])      # MTE2: 加载输入

                with T.SimtVF(threads=threads):
                    # ④ Fragment trick: 向量化加载到寄存器
                    x_frag = T.alloc_fragment((TILE,), "float32")
                    for i in T.Parallel(TILE):
                        x_frag[i] = x_ub[i]

                    # ⑤ 硬件归约: sum(x^2) 从寄存器直接归约（无 UB 往返）
                    sum_sq = T.alloc_reducer((1,), "float32", op="sum", replication="all")
                    T.clear(sum_sq)
                    for i in T.Parallel(TILE):
                        if i < d:
                            sum_sq[0] += x_frag[i] * x_frag[i]
                    T.finalize_reducer(sum_sq)          # 硬件级 warp 归约

                    # ⑥ 计算 rstd
                    var = sum_sq[0] / d + eps
                    rstd_val = T.rsqrt(var)

                    # ⑦ 输出: y = x * rstd * w（复用 x_frag，无需重新加载 x）
                    for i in T.Parallel(TILE):
                        if i < d:
                            y_ub[i] = x_frag[i] * rstd_val * w_ub[i]

                # ⑧ MTE3: 写回 GM
                T.copy(y_ub[:d], Y[base:base+d])
                T.copy(z_rstd_ub[:1], RSTD[row_id:row_id+1])

    return main
```

### 4.4.3 关键设计

| 设计点 | 说明 | 性能影响 |
|--------|------|---------|
| **Fragment trick** | float4 分块加载到寄存器，利用寄存器级并行 | 消除 x 二次 UB 读 |
| **alloc_reducer + finalize_reducer** | 硬件级 warp 归约 | 远快于软件归约 |
| **Double buffer (num_stages=2)** | MTE2 加载与 VEC 计算重叠 | 隐藏 HBM 延迟 |
| **64 cores 全并行** | 每核处理 batch/64 个 token | 最大化并行度 |
| **权重只加载一次** | W 在循环外加载 | 减少GM 往返 |
| **自适应线程数** | d>4096 用 256 线程，否则 128 | 平衡并行度和开销 |

### 4.4.4 性能特征

- Fragment 寄存器复用；double buffer 隐藏延迟；64 核全并行
- 性能结论：d=7168 达 88%+ 带宽（1400+ GB/s）

```python
def topk_gate(num_tokens, num_experts, topk=2, dtype="float32"):

        with T.Kernel(num_cores) as pid:

                        S.vdupv(max_broadcast, max_val)

                        # 比较 + 选择

                        S.vselr(selected, mask, vreg)

                        S.vscatter(topk_indices[token, k], selected_idx)

                        # ③ pad_value 处理不足 K 个的情况
```
